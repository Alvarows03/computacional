ESTUDIANTE 1 — Introducción, problema TSP y objetivos      (2 min 30 s)
Lectura 7
---------------------------------------------------------------------
Decir:
  * Contexto: rutas de reparto, circuitos electrónicos, planificación de
    visitas; siempre hay que decidir el mejor orden para recorrer puntos.
  * Definiciones (Lectura 7): ciclo hamiltoniano = recorrido que empieza y
    termina en el mismo vértice y pasa una sola vez por cada uno. TSP = hallar
    el ciclo hamiltoniano de costo mínimo (distancia, costo o tiempo).
  * Cantidad de ciclos: (n-1)!/2. Ejemplo: n = 5 -> 12 ciclos.
  * Objetivo general (leer tal cual): "Desarrollar un programa en Python que
    resuelva el problema del agente viajero mediante fuerza bruta, con una
    interfaz interactiva que permita construir el grafo, validar ciclos
    hamiltonianos y recorrer paso a paso la búsqueda del ciclo óptimo."
  * Alcance: grafo no dirigido y ponderado, n entre 5 y 10.
Mostrar: diapositiva del problema + paso 1 con el grafo del caso n = 5.
Puente: "Para resolverlo primero hay que modelar el grafo; continúa el
         Estudiante 2."

---------------------------------------------------------------------
ESTUDIANTE 2 — Modelado del grafo y aristas faltantes      (2 min 30 s)
Lectura 5.1
---------------------------------------------------------------------
Decir:
  * Modelo: vértices A..J, aristas no dirigidas con peso positivo. Creación
    manual (formulario o texto "A-B: 5") o aleatoria (densidad, pesos, semilla).
  * Matriz de adyacencia y matriz de caminos: se suma 1 en la diagonal, se
    calcula la matriz de caminos y se reordenan filas/columnas; los bloques
    diagonales de unos son las componentes conexas (Lectura 5.1).
  * Sin conexidad no hay ciclo hamiltoniano. Además se revisan: grado >= 2 y
    puntos de articulación. Condición de Dirac (grado >= n/2): suficiente,
    no necesaria.
  * Si NO hay ciclo, el programa dice cuáles aristas faltan: el MÍNIMO de
    aristas y varias alternativas; el usuario les asigna peso y las agrega.
Mostrar: botón "Ejemplo sin ciclo" -> paso 2 (mensaje rojo, aristas rojas
         discontinuas, "Agregar estas aristas al grafo") -> pasa a válido.
Puente: "Con el grafo ya válido armamos la matriz de costos; sigue el
         Estudiante 3."

---------------------------------------------------------------------
ESTUDIANTE 3 — Matriz de costos y ruta mínima              (2 min 30 s)
Lectura 5.2
---------------------------------------------------------------------
Decir:
  * Grafo ponderado y matriz de costos: peso de cada arista, "infinito" si no
    existe, 0 en la diagonal (equivale a la matriz de distancias de Dijkstra).
  * Acumulado por tramos: la tabla del paso a paso suma arista por arista,
    igual que las etiquetas "acumulado, vértice de origen" de Dijkstra.
  * Comparación con la ruta mínima: Dijkstra elige siempre el menor acumulado y
    es correcto (O(V^2)); esa misma idea voraz en el TSP (vecino más cercano)
    NO garantiza el óptimo.
  * Dato del caso n = 5 (documentación, sección 7.3): vecino más cercano = 39
    (calculado a mano); óptimo = 29. La elección voraz resulta 34,5 % peor.
Mostrar: paso 4 -> matriz de costos con el ciclo óptimo resaltado.
Puente: "Veamos cómo se obtiene el óptimo evaluando todas las rutas; sigue el
         Estudiante 4."

---------------------------------------------------------------------
ESTUDIANTE 4 — Fuerza bruta y complejidad                  (2 min 30 s)
Lecturas 9.1 y 9.2
---------------------------------------------------------------------
Decir:
  * Algoritmo: fijar A, generar las permutaciones de los otros n-1 vértices,
    descartar el sentido inverso, sumar pesos, descartar rutas con arista
    inexistente, guardar el mínimo (mostrar la Figura 3 del diagrama de flujo).
  * Recurrencia: H(n) = (n-1)·H(n-1), H(3) = 1, es decir H(n) = (n-1)!/2
    (ecuación en diferencias de orden 1; coeficiente NO constante, por eso se
    resuelve por iteración y no con la ecuación característica).
  * Lectura 9.2: el costo de evaluar una ruta cumple T(k) = T(k-1) + 1 -> T(k) = k;
    trabajo total n·H(n) = n!/2 -> O(n!).
  * Por qué n entre 5 y 10: n = 10 -> 181 440 ciclos (~0,3 s); n = 12 -> casi 20
    millones; n = 15 -> ~4,4 x 10^10; n = 20 -> ~1 900 años a 10^6 ciclos/s.
Mostrar: paso 3 -> "Ejecutar fuerza bruta", "Siguiente", "Sig. mejora ★"
         (en el caso n = 5: 41 -> 40 -> 34 -> 29); y la tabla de complejidad
         de la sección 5.2 de explicacion_codigo.md (llevarla en una diapositiva).
Puente: "Ahora vemos la interfaz completa y cómo está organizada; sigue el
         Estudiante 5."

ESTUDIANTE 5 — Interfaz, visualización y arquitectura      (2 min 30 s)
---------------------------------------------------------------------
Decir / hacer (demostración en vivo, sin leer):
  * Recorrido rápido: barra lateral (n, modo) -> pasos 1 a 4.
  * Paso a paso: Siguiente/Anterior, +10, +100, "Sig. mejora"; la ruta se
    dibuja sobre el grafo (verde = válida, roja discontinua = arista
    inexistente). Casilla "solo ciclos válidos".
  * Resultado: número de ciclos, costo de cada ciclo (tabla ordenada),
    ciclo óptimo resaltado en naranja.
  * Arquitectura modular (Figura 1): app.py (menú), graph_manager.py y
    tsp_solver.py (la LÓGICA), paso_1 a paso_4 (una PANTALLA por paso) y
    ui_components.py (dibujo y tablas). El código usa solo funciones, for e
    if; tiene 12 pruebas automáticas.
Mostrar: la aplicación en vivo (grafo aleatorio con n = 8 o 9 para ver muchas
         rutas).
Puente: "Cerramos con las conclusiones y cómo ejecutar y publicar el
         sistema; el Estudiante 6."

---------------------------------------------------------------------
ESTUDIANTE 6 — Conclusiones, lecturas y despliegue         (2 min 30 s)
---------------------------------------------------------------------
Decir:
  * Conclusiones (resumen):
      1) Se cumplió el objetivo: programa en Python que valida el grafo, informa
         aristas faltantes, muestra el paso a paso y halla el ciclo óptimo.
      2) La fuerza bruta es exacta pero O(n!): por eso n <= 10.
      3) Una decisión voraz (vecino más cercano) no garantiza el óptimo.
      4) Separar lógica e interfaz permitió probar el algoritmo de forma
         independiente.
  * Lecturas aplicadas: 7, 5.1, 5.2 (directas); 9.1 y 9.2 (complejidad);
    6.1 y 6.2 (contraste: el flujo máximo es polinomial y se certifica con un
    corte mínimo; el TSP no).
  * Lecturas no aplicables y por qué: 1, 2.1, 2.2, 3.x (imágenes e
    histogramas), 4.1-4.3 (aritmética modular y RSA), 8 (Huffman: compresión).
  * Ejecución local: python -m venv venv -> activar -> pip install -r
    requirements.txt -> abrir ejecutar.py y pulsar ▶ (o python -m
    streamlit run app.py). Sin internet.
  * Despliegue gratuito: subir a GitHub y publicar en Streamlit Community Cloud
    (app.py como archivo principal); alternativa Render; opcional Supabase para
    guardar ejecuciones.
Mostrar: diapositiva de conclusiones + URL o código QR de la app.
